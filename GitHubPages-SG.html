1
Create the Repository
A repository is a folder on GitHub that stores your files. To turn it into a website automatically, the naming must be flawless.
  • Select New repository.
  • Set name exactly to: YOUR-USERNAME.github.io
  • Set visibility to Public.
  • Check Add a README file, then Create.
2
Build the "Front Door"
A website needs a starting point. When someone visits your URL, their browser automatically looks for a specific file to open first.
  • Select Add file > Create new file.
  • Name it exactly: index.html
  • Paste your starter HTML code into the editor.
  • Personalise your name, introduction, and links.
3
Commit (Save) Your Work
GitHub doesn't auto-save. A "commit" is a permanently saved version of your project, packed with a note explaining what you changed.
  • Select Commit changes...
  • Write a clear message (e.g., "Create home page").
  • Select Commit directly to main branch.
  • Do this every time you upload an image or edit code.
4
Activate & Publish
Tell GitHub to convert this folder into a live website. (Note: Publishing takes a minute. If it 404s at first, wait and refresh).
  • Go to repository Settings > Pages.
  • Under Source, select Deploy from a branch.
  • Under Branch, select main and /(root).
  • Select Save. Visit https://YOUR-USERNAME.github.io
🩴 Chancleta Alerts (Fatal Errors)

1. The URL Trap

Do not submit your repository editing link to your instructor/client. Submit the published public website.

github.com/janetan/janetan... https://janetan.github.io

2. The Case-Sensitivity Trap

Servers care about capital letters. If your code calls for an image, the filename must match perfectly.

<img src="profile.jpg"> + Profile.JPG <img src="profile.jpg"> + profile.jpg

3. The Privacy Trap

If you wouldn't pin it to a public noticeboard, do not push it to GitHub. It is visible to the entire world.

Student ID, Passwords, Phone # Professional Bio, LinkedIn, Email
